# MVP Readiness Operations

This note captures small operational readiness items that support the MVP pilot
without changing participant or reviewer product scope.

## Spending Alert And Budget Monitoring

Cost monitoring is observational during the MVP. Before any real participant
pilot, configure project-level spending visibility outside the application:

1. Set an OpenAI project budget or spending alert for the API project used by
   the MVP environment.
2. Confirm the alert recipients include the pilot owner and the technical owner.
3. Record the alert threshold and owner in the deployment checklist for the
   target environment.
4. During E2E testing, compare the application-level estimated live,
   analysis, and total costs with the provider billing view.

The application already records live usage, analysis usage, estimated live cost,
estimated analysis cost, total estimated cost, and session cost category. Do not
add an in-app dashboard or aggregate spend report for MVP readiness.

## Typecheck And Build Order

`npm run typecheck` removes `.next/types` before running TypeScript. This keeps
standalone typechecks from reading stale route types generated by a previous
Next build.

Recommended local verification order:

```powershell
npm run typecheck
npm run lint
npm test
npm run build
```

If migrations, RPCs, RLS, storage SQL, or generated database types changed, run:

```powershell
npm run db:reset
npm run db:types
npm run typecheck
npm test
```
